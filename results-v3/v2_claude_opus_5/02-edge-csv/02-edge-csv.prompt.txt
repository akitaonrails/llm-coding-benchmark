# Task 02 — Edge-case correctness: a strict RFC-4180 CSV record parser

**Category:** edge-case correctness · **Language:** Go

## Goal

Implement `csvkit.ParseRecord(line string) ([]string, error)` in `csvkit/csv.go`.
It parses **one** CSV record (no embedded newlines) into its fields, strictly per
the grammar below. The starter implementation is naive (`strings.Split`) and wrong.

## Grammar (follow it exactly)

- Fields are separated by **commas** (`,`) at the top level.
- A field is either **quoted** or **unquoted**:
  - **Quoted** — the field begins with `"` (as its very first character). It ends
    at the next `"` that is not part of an escaped pair. Inside a quoted field, a
    literal double-quote is written as **two double-quotes** (`""`). Everything
    between the opening and closing quote (with `""` collapsed to `"`) is the field
    value, verbatim (spaces, commas, and unicode included).
  - **Unquoted** — any field that does not begin with `"`. It runs until the next
    top-level comma or end of line, verbatim (leading/trailing spaces are
    **significant** — do not trim).
- **Errors** (return a non-nil error; the standard `csvkit.ErrMalformed` is fine):
  - a `"` appears anywhere in an **unquoted** field (e.g. `ab"c`, or `  "x"` — note
    the leading space means the quote is *not* a field opener);
  - any characters appear **after a closing quote** before the next comma / EOL
    (e.g. `"a"b`);
  - a quoted field is **unterminated** (EOL before the closing quote).
- The empty string is a single empty field: `ParseRecord("")` → `[]string{""}`.
- A trailing comma yields a trailing empty field: `"a,b,"` → `["a","b",""]`.

## Visible examples

| input | output |
|---|---|
| `a,b,c` | `["a","b","c"]` |
| `a,"b,c",d` | `["a","b,c","d"]` |
| `a,"b""c",d` | `["a",` `b"c` `,"d"]`  (the middle field is `b"c`) |
| `"",x` | `["","x"]` |
| `a,,c` | `["a","","c"]` |
| `""""` | one field containing a single `"` |
| `` (empty) | `[""]` |
| `ab"c` | error |
| `"a"b` | error |
| `"unterminated` | error |
